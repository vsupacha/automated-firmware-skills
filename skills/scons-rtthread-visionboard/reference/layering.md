# Stage 3 - Layered code (RT-Thread)

```
src/hal_entry.c      execution: hal_entry() in RT-Thread's main thread (init, banner, loop/poll)
  │ uses              + msh commands (MSH_CMD_EXPORT_ALIAS) run by the tshell thread
src/func/*.c/.h      services in C: led (1-based, pin read-back), button (debounce timed with
  │ uses              rt_tick_get_millisecond(), events)
src/board/board_io.* board adaptation: pin table (BSP_IO_PORT_xx_PIN_yy), rt_pin_mode/write/read,
  │ uses              BOARD_xxx #if tables, BOARD_ID_NAME
RT-Thread 5.0.2      kernel (threads, ticks, rt_kprintf), pin + serial device drivers
  │                   (libraries/HAL_Drivers), msh on uart9
FSP 5.1.0            ra/ ra_gen/ ra_cfg/ (generated by the SDK - do not edit), startup, clocks
```

Call chain: reset → FSP startup (`ra/`) → RT-Thread `rtthread_startup` → main thread →
`main()` (ra_gen/main.c) → `hal_entry()`.

Rules
- Pins and `rt_pin_*` only in `src/board/`. The header is `board_io.h` because the BSP's
  `board/board.h` is on the include path; include it as `"board/board_io.h"` (hal_entry.c) or
  `"../board/board_io.h"` (func/).
- `func/` may use the kernel API (`rtthread.h`: ticks, `rt_tick_t`) but no pins, no devices and no
  printing; it never includes `hal_data.h` or FSP headers.
- `hal_entry.c` owns the threads and the console: `rt_kprintf` for output, msh commands for input.
  A command name is a C identifier (no `?`), the description is bare tokens (no commas).
- `src/board` and `src/func` are compiled with `-Wextra` (src/SConscript), hal_entry.c with the
  project's `-Wall`; the build gate allows 0 warnings in `src/`.
- Change RT-Thread components with RT-Thread Settings in Studio (or menuconfig): it rewrites
  `rtconfig.h` - rebuild with build.sh afterwards.

## Console protocol (test contract, msh flavour)

| Line | Meaning |
| --- | --- |
| `READY` | boot finished / answer to `info` (printed after `INFO ...`) |
| `INFO app=<name> v=<ver> board=<id> ...` | identity - the test checks `board=<id>` |
| `OK ...` / `ERR <reason>` | command result |
| `EVT ...` | asynchronous event (`EVT btn1=pressed name=KEY0 pin=P907 led1=1`) |
| `<TAG> k=v ...` | state report: `led` -> `LED led1=0 led2=0 led3=0`, `btn` -> `BTN btn1=0` |
| `msh />` | RT-Thread's prompt (lines may follow it: specs match without `^`) |
| `<cmd>: command not found.` | msh's answer to an unknown command |
